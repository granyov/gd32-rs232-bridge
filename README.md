# Lazarus SoftW RS232

> **В разработке:** конфигурируемая версия **1.2.0-dev** доступна в отдельной ветке. Последний опубликованный проверенный на плате комплект — **1.1.0** с фиксированными параметрами. Не путайте исходники разработки и выпущенные HEX/BIN.

**Lazarus SoftW RS232** — микропрограммное обеспечение интерфейсных контроллеров промышленного компьютера **LAZARUS UVON**. Оно обеспечивает работу портов, обозначенных на лицевой панели как **V.24**, в асинхронном режиме **RS-232**.

Прошивка реализует прозрачный двунаправленный мост между UART хоста **RK3568** и линией RS-232 через трансивер **MAX3238**. Контроллер — **GD32F103C8T6** (DD9/DD11 на описанной интерфейсной плате), внешний кварц **16 МГц**. Опубликованный проверенный комплект прошивки — **1.1.0**.

**Аппаратная проверка:** подтверждён обмен с ACE Instrument ADL-200A: получены ответы времени/даты и данные измерения, опубликованные приложением хоста в MQTT. Это пример совместимого устройства, **не назначение прошивки**: Lazarus SoftW RS232 не разбирает протокол ADL-200A и не реализует MQTT.

## V.24 и RS-232 в УВОН

**V.24** — обозначение портов на передней панели LAZARUS UVON и стандарт, описывающий функции интерфейсных сигналов. **RS-232** — режим последовательного обмена, реализованный данной прошивкой и трансивером на плате. Название V.24 не означает, что этот образ поддерживает синхронную передачу, все модемные цепи или произвольную конфигурацию последовательного порта.

На плате присутствуют два контроллера **DD9** и **DD11**. Для них в документации ниже указаны пути Linux, разъёмы платы и SWD, определённые по предоставленной схеме. **Соответствие надписей V.24 1/2 на лицевой панели внутренним XP7/XP9 отдельно не подтверждено**; проверяйте его по разводке конкретного УВОН, а не по порядку строк таблицы.

Прошивка предназначена для асинхронного прозрачного обмена произвольными байтами. Названия параметров сборки `HOST_BAUD` и `LOGGER_BAUD` исторические: второе обозначает скорость **внешней стороны RS-232**, а не ограничивает прошивку подключением логгера.

## Насколько прошивка универсальна

| Свойство | Поддержка |
|---|---|
| Протокол устройства | Любой поток байтов: ASCII и бинарные протоколы, без разбора команд/ID |
| Передача | Асинхронная, полный дуплекс; без преобразования байтов и окончаний строк |
| Опубликованные HEX/BIN v1.1.0 | **38400 ↔ 38400 бод, 8N1** |
| Скорость в v1.2.0-dev | 1200–115200 бод независимо для UART хоста и внешнего RS-232; сохраняется во Flash, выбирается при запуске |
| Формат кадра v1.2.0-dev | 8N1/8N2, 8E1/8E2, 8O1/8O2, 7E1/7E2, 7O1/7O2; параметры сторон независимы |
| Flow control | В опубликованной v1.1.0 отсутствует. В v1.2.0-dev — опциональное программное RTS/CTS на внешнем RS-232 (DTR постоянно активен, DSR не используется) |
| XON/XOFF | Байты передаются как обычные данные, управление потоком не реализовано |
| Настройка v1.2.0-dev | Сохранение в двух Flash-слотах через SWD без пересборки; применяется **после reset**. Автопоиска скорости и команд управления через UART нет |
| Плата УВОН | GD32F103C8T6, HXTAL 16 МГц, выводы и MAX3238 по описанной схеме |
| HDLC, синхронный USART, RS-485 | Не поддерживаются этим образом |
| BREAK и модемные сигналы хоста | Не ретранслируются |

Это универсальный **по содержимому данных** мост для конкретной аппаратной схемы и настроек линии УВОН. В версии разработки **7-битный режим пропускает только младшие 7 бит**; преобразования кодировок нет. Готовый образ не подходит автоматически любой RS-232 плате. Обе стороны должны использовать согласованные параметры. Изменение `stty` на Linux не перенастраивает USART контроллера.

Для разных скоростей предусмотрены отдельные очереди; если входящий поток постоянно быстрее исходящего, конечная очередь переполнится. Без flow control это нельзя устранить одним увеличением буфера. При переполнении отбрасывается новый байт; ошибки и потери учитываются в `bridge.stats`, доступном через SWD. Полезная вместимость — 2047 байт на направление.

## Готовая прошивка

Выпущенные образы **v1.1.0** оставлены без изменения: их имена файлов и встроенная строка идентификации ещё используют прежнее техническое обозначение `lazarus-gd32-rs232`. Это необходимо для сохранения проверенных артефактов и контрольных сумм. Новые сборки из исходного кода имеют идентификатор **Lazarus SoftW RS232 1.2.0-dev** и требуют отдельной проверки на устройстве перед публикацией как готового релиза.

- [HEX, 38400/38400, 8N1](firmware/lazarus-gd32-rs232-hse16000000-38400-38400.hex)
- [BIN, 38400/38400, 8N1](firmware/lazarus-gd32-rs232-hse16000000-38400-38400.bin)
- [SHA-256](firmware/SHA256SUMS)
- [Параметры сборки и проверка](firmware/BUILD_INFO.json)
- [Распиновка и инструкция прошивки](docs/BOARD_AND_FLASHING.md)
- [Конфигурация 1.2.0-dev и безопасное восстановление](docs/CONFIGURATION.md)

**Адрес BIN: `0x08000000`.** HEX уже содержит адреса. Перед записью сохраните старую прошивку. Это прошивка контроллера интерфейсной платы; в ADL-200A её загружать нельзя.

По предоставленной схеме `/dev/ttyS5` соответствует DD9, RS-232 XP7, SWD XP6; `/dev/ttyS4` — DD11, RS-232 XP9, SWD XP8. Маркировку внешних разъёмов V.24 1/2 с этими обозначениями нужно сверить на конкретной плате. Нумерация Linux зависит от конфигурации хоста. Один образ поддерживает оба контроллера с одинаковой разводкой. В проведённой проверке логгер отвечал на **`/dev/ttyS5`**.

## Сборка и проверки

Нужны GNU Make, Arm GNU Toolchain (проверено с 14.3.Rel1 / GCC 14.3.1), Python 3. Для тестов очередей — компилятор хоста с AddressSanitizer и UndefinedBehaviorSanitizer.

```sh
make -j4 all verify
make test
```

Если компилятор отсутствует в PATH:

```sh
make -j4 all verify PREFIX=/path/to/bin/arm-none-eabi-
```

Вариант 9600 бод на обеих сторонах:

```sh
make -j4 all verify HOST_BAUD=9600 LOGGER_BAUD=9600
```

Артефакты разработки v1.2.0-dev с префиксом `lazarus-softw-rs232-` создаются в `build/hse16000000-host<HOST_BAUD>-logger<LOGGER_BAUD>/`. При переходе на 9600 необходимо также настроить хост и само подключённое устройство. В версии разработки параметры по умолчанию задаются Makefile, но могут быть переопределены корректной конфигурацией Flash (см. руководство). **Физически проверен режим 38400/38400.** Изменять HSE для описанной платы не нужно: частота, отличная от 16 МГц, запрещена проверкой компиляции.

`make test` проверяет двунаправленный обмен 234000 байт, циклические переходы очередей, переполнение и продолжение приёма после ошибок. В ветке разработки также проверяются CRC, выбор конфигурационного слота и валидация настроек. `make verify` проверяет HEX/BIN, контрольные суммы, векторы прерываний и границы памяти.

## Проверка на плате

30.09.2026 пользователь сообщил о записи образа. Через SSH на хосте подтверждены:

- корректные ответы `GTT` и `GDD` от ADL-200A, ID 1, через `/dev/ttyS5`, 38400, 8N1;
- ответ на измерение: канал 2, 98 байт исходных данных;
- публикация в `adl200a/measurement`, журнал: `Published 1 channels (98 raw bytes)`.

Приложение хоста: [adl200a-mqtt](https://github.com/granyov/adl200a-mqtt). Проверка охватывает одно подключение и короткий цикл обмена. Длительная нагрузка, другие скорости, все каналы и чтение Flash MCU после записи не проверялись.

## Устройство проекта

- `Core/Src/main.c` — GD32 USART0/USART1, GPIO, IRQ, watchdog и строка идентификации Lazarus SoftW RS232.
- `Core/Src/config.c` — разбор настроек из защищённой CRC пары Flash-слотов, заводские параметры.
- `tools/uvon_rs232_config.py` — утилита подготовки страниц настроек через SWD.
- `Core/Src/bridge.c` — очереди и счётчики ошибок, независимо от периферии.
- `Core/Startup/` — GCC startup для GD32F10x MD.
- `GD32F103C8_FLASH.ld` — Flash 64 КиБ, SRAM 20 КиБ.
- `Drivers/` — официальные заголовки CMSIS и библиотека GigaDevice.
- `SDK_CHANGES.patch` — изменения конфигурации тактирования и исправление условной компиляции SDK.
- `tests/` — тесты очередей и проверка образа.

SDK: [GigaDevice GD32F10x Firmware Library](https://github.com/GigaDevice-GD32-MCU/GD32F10x_Firmware_Library), commit `23a80f96368336b4d47014da33cd9b7ba550165e`. HXTAL, ядро и обе шины APB работают на 16 МГц, PLL выключен. PC13 не используется, SWD остаётся доступным.
