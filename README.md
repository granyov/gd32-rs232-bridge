# Lazarus SoftW RS232

**Lazarus SoftW RS232 1.2.0** — рабочая программная сборка прошивки интерфейсных контроллеров **V.24 / RS-232** промышленного компьютера **LAZARUS UVON**. Реализует прозрачный двунаправленный обмен между UART процессора RK3568 и внешним RS-232 через MAX3238. Разработана для двух микроконтроллеров **GD32F103C8T6** (DD9 и DD11).

> **Статус:** исходный код 1.2.0 собирается для ARM Cortex-M3 и проходит программные тесты, проверку HEX/BIN и контроль диапазонов Flash/RAM. **Непосредственные испытания 1.2.0 на портах УВОН ещё не проведены.** Ранее на оборудовании проверен только образ 1.1.0 с 38400 бод, 8N1. До промышленного применения новой версии обязательны проверка на конкретной плате и резервное копирование её исходной Flash.

Новая версия собирается из текущих исходников, а опубликованные образы находятся в ZIP-архиве GitHub Releases.

**Для BIN адрес записи — `0x08000000`**. В Intel HEX адреса уже заданы. Не перепрошивайте RK3568, внешний прибор либо соседний GD32 по ошибке.

## Для чего предназначена

На лицевой панели УВОН интерфейсы подписаны **V.24**. Эта прошивка обеспечивает **асинхронный режим RS-232**. Термин V.24 описывает функциональное назначение сигналов и не означает наличие синхронного режима, HDLC или автоматической поддержки всех модемных цепей.

Прошивка не содержит прикладных протоколов. Передаваемые данные могут быть текстовыми или бинарными; мост не добавляет команды, баннеры, окончания строк и не анализирует адреса устройств. Пример использования — обмен с ACE Instrument ADL-200A, но **прошивка не привязана к логгеру** и не содержит MQTT.

## Возможности 1.2.0

| Параметр | Значение |
|---|---|
| Микроконтроллер | GD32F103C8T6, Cortex-M3, Flash 64 КиБ, SRAM 20 КиБ |
| Тактирование | Внешний кварц 16 МГц, ядро/APB1/APB2 16 МГц |
| Передача | Асинхронная, двунаправленная, полный дуплекс |
| Скорости | 1200–115200 бод, отдельно UART хоста и внешний RS-232 |
| Форматы | 8N1, 8N2, 8E1, 8E2, 8O1, 8O2, 7E1, 7E2, 7O1, 7O2 |
| Настройки по умолчанию | **38400/38400, 8N1, без flow control** |
| Управление потоком | Без управления либо программное RTS/CTS **только внешней стороны** |
| Буферы | По 2048 байт на направление, полезная ёмкость 2047 байт |
| Защита | Учёт ошибок USART, watchdog, CRC32 настроек |
| Сохранение | Два слота Flash по 1024 байта с выбором по номеру записи и CRC |
| Изменение параметров | Подготовка образа конфигурации и запись через **SWD**, вступает в силу после reset |
| Восстановление | SWD и заводские параметры при отсутствии валидных записей |
| Не поддерживаются | RS-485, HDLC, синхронный обмен, XON/XOFF, настройка через UART, автоопределение скорости |

При использовании 7-битной стороны старший бит байта отбрасывается: преобразование 8 бит ↔ 7 бит **не сохраняет исходные 8-битные данные**. Если отправитель постоянно быстрее приёмника, буфер может переполниться. При переполнении новый байт теряется, счётчики ошибок доступны по SWD. Линии DTR остаются активными; DSR не управляет потоком. Для RTS/CTS нужна **реальная подключённая цепь CTS**, иначе передача может остановиться.

## Соответствие плат и разъёмов

| Порт Linux (по схеме) | Контроллер | Внешний RS-232 на плате | SWD |
|---|---|---|---|
| `/dev/ttyS5` | DD9 | XP7 (через MAX3238 DD10) | XP6 |
| `/dev/ttyS4` | DD11 | XP9 (через MAX3238 DD12) | XP8 |

**Внимание:** соответствие именно надписей **V.24 1/2 на передней панели** этим разъёмам не подтверждено испытанием; перед прошивкой проверьте разводку конкретного экземпляра. Названия `ttyS4`/`ttyS5` зависят от конфигурации Linux на RK3568.

## Как прошить

1. Определите необходимый DD9 или DD11 и его SWD-разъём. Остановите приложение Linux, использующее соответствующий порт.
2. Подключите совместимый SWD-программатор по сигналам GND, NRST, SWCLK, SWDIO и VTref 3,3 В. Ориентацию и контакты **проверяйте по плате**.
3. До записи сохраните **полные 64 КиБ Flash** и option bytes. Не отключайте защиту чтения автоматически: это может стереть данные.
4. Запишите **HEX**, либо **BIN начиная с `0x08000000`**, выполните verify и перезапустите контроллер.
5. Для сохранения настроек 1.2.0 **не используйте mass erase**: страницы `0x0800F800` и `0x0800FC00` предназначены для конфигурации. При первой установке на устройство с неизвестной Flash изучите её состояние.
6. Проверьте обмен на согласованных параметрах UART Linux и внешнего прибора. Отсутствие связи не подтверждает неисправность прошивки — проверьте скорость, разводку и CTS.

Полная **[инструкция по SWD и разводке](docs/BOARD_AND_FLASHING.md)** и **[настройка двух слотов Flash, восстановление и примеры команд](docs/CONFIGURATION.md)**.

## Настройка без пересборки

Версия 1.2.0 считывает настройки из двух последних страниц Flash при запуске; сама их не записывает. Утилита `tools/uvon_rs232_config.py` работает с дампами этих страниц и создаёт файл для записи через SWD.

```sh
python3 tools/uvon_rs232_config.py show --slot-a slot_a.bin --slot-b slot_b.bin
python3 tools/uvon_rs232_config.py prepare \
  --slot-a slot_a.bin --slot-b slot_b.bin \
  --host-baud 38400 --host-frame 8N1 \
  --rs232-baud 9600 --rs232-frame 8N1 \
  --flow none --output rs232-config.bin
```

Выбирается **неактивный слот**. Адрес записи выводит утилита; нельзя подставлять адрес из примера наугад. После SWD-записи следует проверить считанную страницу командой `verify` и перезапустить GD32. Если обе записи повреждены или отсутствуют, при следующем старте используются заводские настройки сборки.

## Сборка из исходников

Требуются GNU Make, Arm GNU Toolchain (`arm-none-eabi-gcc`), Python 3 и для тестов компилятор хоста с AddressSanitizer/UBSan.

```sh
make -j4 all verify
make test
python3 tools/package_website.py
```

Образы и ELF/MAP создаются в `build/hse16000000-host38400-logger38400/`, архивы — в `dist/`. Параметры `HOST_BAUD` и `LOGGER_BAUD` определяют значения **по умолчанию при отсутствии валидной конфигурации Flash**; имя `LOGGER_BAUD` историческое и означает внешнюю сторону RS-232.

GitHub Actions выполняет тесты, кросс-компиляцию, проверку векторов прерываний, памяти, HEX/BIN и создаёт ZIP для сайта. **Прохождение CI не заменяет тест с реальным GD32/MAX3238.**
