# Lazarus SoftW RS232 — плата УВОН и программирование

**Lazarus SoftW RS232** — прошивка микроконтроллеров последовательных портов **V.24** промышленного компьютера **LAZARUS UVON**, работающих в асинхронном режиме **RS-232**. Здесь описаны аппаратная конфигурация, ограничения и программирование **GD32F103C8T6**. Проверенный опубликованный образ имеет версию **1.1.0**.

Схема — предоставленный документ «Э3.pdf», листы 8 и 9. На плате: кварцы BQ3/BQ4 DSX321G-16MHz; между UART хоста RK3568 и внешним интерфейсом RS-232 работает GD32F103C8T6 и трансивер MAX3238. Это прошивка **интерфейсного контроллера УВОН**, а не самого УВОН, не Linux и не подключённого прибора ADL-200A.

## Готовый образ

В каталоге `firmware/` репозитория находятся ранее собранные и проверенные **HEX/BIN v1.1.0**. Их исходные имена `lazarus-gd32-rs232-...` и встроенный идентификатор сохранены для воспроизводимости и неизменности контрольных сумм. Новые сборки версии **1.2.0-dev** носят имя `lazarus-softw-rs232-...`; ELF, MAP, HEX и BIN создаются в `build/hse16000000-host38400-logger38400/`.

- Микроконтроллер: **GD32F103C8T6**, Cortex-M3, Flash 64 КиБ, SRAM 20 КиБ.
- Кварц: **16 МГц**. Ядро, APB1 и APB2: 16 МГц, PLL выключен.
- Обе стороны: **38400 бод, 8 бит, без чётности, 1 стоп-бит**.
- Аппаратный и программный flow control не используются; RTS/DTR постоянно активны.
- Аппаратный делитель каждого UART: 417; расчётная скорость 38369,3 бод (−0,080%). Это расчёт по номиналу кварца, не измерение на плате.
- Начало Flash: **0x08000000**. HEX содержит адреса; для BIN указать этот адрес вручную.
- Один и тот же образ подходит DD9 и DD11 по предоставленной схеме.
- Образы STM32 версии 1.0.0 заменены этим комплектом; используйте версию GD32 1.1.0.

## Выбор контроллера

| Порт Linux | Контроллер | Кварц | RS-232 на плате | Разъём SWD |
|---|---|---|---|---|
| `/dev/ttyS4` | **DD11** | BQ4, 16 МГц | **XP9**, через DD12 | **XP8** |
| `/dev/ttyS5` | DD9 | BQ3, 16 МГц | XP7, через DD10 | XP6 |

Соответствие портов Linux и внутренних разъёмов выведено из связей UART4/UART5 на листе 1 и SOM_GD32_2/SOM_GD32_1 на листах 8–9. **Порядок V.24 1/2 на лицевой панели не подтверждён этой таблицей.** Перед программированием проверьте соответствие DD/XP внешним разъёмам конкретного устройства. При проверке после прошивки рабочим портом оказался `/dev/ttyS5`.

## Подключение программатора

Нумерация контактов **по схеме**, ориентацию колодки на плате сверить по маркировке:

| Контакт XP8 / XP6 | Сигнал | Контакт MCU |
|---|---|---|
| 1 | GND | Общая земля |
| 2 | NRST | 7 |
| 3 | SWCLK | PA14, 37 |
| 4 | SWDIO | PA13, 34 |
| 5 | VCC3V3_SYS / VTref | Опорное напряжение 3,3 В |

Использовать SWD-программатор и программу с поддержкой GD32F103C8. Плату питать штатно, контакт 5 использовать как VTref согласно инструкции программатора; не соединять два независимых источника питания. Линии SWD — логические 3,3 В, не RS-232.

1. Остановить опрос логгера на Linux: `sudo systemctl stop adl200a`.
2. Подключиться по SWD, проверить тип MCU и сохранить резервную копию Flash (64 КиБ с 0x08000000) и сведения об option bytes. Если чтение закрыто, не снимать защиту автоматически: её снятие может стереть старую прошивку.
3. Записать HEX из `firmware/`, выполнить проверку записанного содержимого. Для BIN адрес 0x08000000. Option bytes и BOOT0 для этой прошивки менять не требуется.
4. Перезапустить MCU, отсоединить программатор. Подключить логгер к соответствующему RS-232 разъёму.
5. В `/etc/default/adl200a` проверить фактический порт (в проверенном подключении `/dev/ttyS5`), скорость 38400, режим 8N1, ID логгера 1. Запустить `sudo systemctl start adl200a`, смотреть `sudo journalctl -u adl200a -f`.

## Разводка и поведение

| Назначение | Вывод MCU | Соединение |
|---|---|---|
| К RK3568, TX | PA9 / USART0_TX | SOM_GD32_n_UART_RX |
| От RK3568, RX | PA10 / USART0_RX | SOM_GD32_n_UART_TX |
| RS-232 TX | PA2 / USART1_TX | MAX3238 DIN1 → TD, XP7/XP9 контакт 3 |
| RS-232 RX | PA3 / USART1_RX | MAX3238 ROUT1 ← RD, контакт 2 |
| RS-232 земля | — | XP7/XP9 контакт 5 |
| RTS | PA1 | Контакт 7; активен постоянно |
| DTR | PA4 | Контакт 4; активен постоянно |
| CTS / DSR | PA0 / PA5 | Не используются для ограничения передачи |
| MAX3238 | PB1 / PB2 | FORCEOFF_n=1, FORCEON=1 |

Lazarus SoftW RS232 пересылает байты в обе стороны без преобразования протокола, баннеров и команд. Сигналы V.24 в этом образе ограничены описанными линиями RS-232; реализации синхронного режима нет. ID 1 задаётся программой опроса, мост не разбирает адреса устройств. HDLC, программный синхронный UART и тактовые импульсы удалены. PC13 не используется: в схеме он NC. RTS/DTR выставлены TTL 0, MAX3238 инвертирует их в положительный уровень RS-232.

На каждое направление выделена очередь 2048 байт (полезная вместимость 2047). При переполнении отбрасывается новый байт, счётчики доступны по SWD в `bridge.stats`. При ошибках framing/noise/parity повреждённый байт отбрасывается, приём продолжается. Watchdog работает от IRC40K, номинальный таймаут около 3,2 с, обновление каждые 500 мс. Если внешний кварц не запускается, инициализация останавливается; скрытого перехода на неточный внутренний генератор нет.

## Проверки и ограничения

Успешно: сборка GCC с `-Wall -Wextra -Werror`; тест очередей на хосте с AddressSanitizer/UndefinedBehaviorSanitizer (234000 байт в двух направлениях, циклические переходы, переполнение, ошибки и восстановление); проверка соответствия BIN/HEX, контрольных сумм Intel HEX, адресов векторов Reset/SysTick/USART0/USART1 и границ Flash/SRAM.

Размер BIN — 3188 байт. Статические данные занимают 4176 байт SRAM; дополнительно зарезервировано 1536 байт для heap/stack, всего 5712 байт.

**30 сентября 2026 года после записи прошивки пользователем подтверждён обмен с ADL-200A через `/dev/ttyS5`, 38400, 8N1, ID 1.** Получены корректные ответы GTT/GDD и измерения канала 2; программа adl200a-mqtt опубликовала один канал (98 байт исходного ответа). На `/dev/ttyS4` ответов не было. Служба переведена на `/dev/ttyS5`. Это функциональная проверка одного подключения, не длительный нагрузочный тест и не подтверждение всех скоростей. Какой именно MCU был физически прошит, отдельно не проверялось; соответствие DD/XP приведено по схеме.

## Настраиваемая версия 1.2.0-dev

В **отдельной ветке разработки** добавлено чтение конфигурации Flash при загрузке (два 1 КиБ слота, CRC32 и последовательные номера). Поддерживаются режимы 7E/7O/8N/8E/8O с одним или двумя стоп-битами и программное RTS/CTS только для внешнего RS-232 через PA0/PA1. Старые опубликованные HEX/BIN версии 1.1.0 эти функции не содержат.

Полная схема записи параметров, использования неактивного слота и восстановления настроек: [CONFIGURATION.md](CONFIGURATION.md). **Если CTS физически не подключён или не управляется партнёром, включать RTS/CTS нельзя: передача может остановиться.** Различие форматов на сторонах может приводить к потере восьмого бита в 7-битном режиме.

## Повторная сборка

Нужны GNU Make, Arm GNU Toolchain и Python 3. Для `make test` — также компилятор хоста с ASan/UBSan.

```sh
make -j4 all verify PREFIX=/path/to/arm-none-eabi-
make test
```

`PREFIX` включает завершающий дефис. Проверенная версия GCC: 14.3.1 (Arm GNU Toolchain 14.3.Rel1). Например, для отдельного варианта 9600 бод на обеих сторонах: `make all verify HOST_BAUD=9600 LOGGER_BAUD=9600`. Готовый, проверенный комплект **1.1.0** содержит только **38400/38400** и сохраняет первоначальные имена файлов. Для сборки с новым именем Lazarus SoftW RS232 необходимо заново выполнить `make all verify`, а перед размещением новых HEX/BIN в `firmware/` — проверить их на плате и обновить `BUILD_INFO.json` и `SHA256SUMS`. При изменении скорости моста необходимо согласовать её с Linux и логгером. HSE=8000000 для этой платы запрещён проверкой компиляции.

## Источники и изменения SDK

Использована [официальная библиотека GD32F10x](https://github.com/GigaDevice-GD32-MCU/GD32F10x_Firmware_Library), commit `23a80f96368336b4d47014da33cd9b7ba550165e`. Регистры, память и функции выводов сверены с [GD32F103xx Datasheet Rev2.12](https://gd32mcu.com/data/documents/datasheet/GD32F103xx_Datasheet_Rev2.12.pdf). Полярность управления трансивером сверена с [MAX3238E TI](https://www.ti.com/product/MAX3238E). Разводка — предоставленная пользователем схема «Э3.pdf».

В `system_gd32f10x.c` изменено: выбран прямой HXTAL; APB1 /1 для одинаковых делителей UART; закрывающий `#endif` перенесён перед `SystemCoreClockUpdate`, иначе SDK компилировал эту функцию только в последнем варианте настройки тактирования. Diff включён в `SDK_CHANGES.patch`.

GCC startup написан для этого проекта, порядок 65 векторов взят из официального MD startup. Linker ограничивает Flash/RAM размером C8. Библиотека и лицензионные уведомления включены в `Drivers/`; исходный HDLC код не линкуется.
